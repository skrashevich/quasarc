# quasarc

`quasarc` читает состояние Алисы, Wi-Fi и других сервисов локальной шины Quasar на Яндекс Станции 2 (Linux) и Станции Макс (Android). Он также управляет громкостью через родные RPC обеих моделей. На колонке его можно запускать как отдельную команду и получать JSON. В Go-приложении те же данные доступны через пакет `station`.

## Установка на Станцию

На компьютере понадобится Go 1.27.1 или новее. На колонке нужен настроенный доступ к командной строке и право запускать файлы из каталога установки. Go нужен только для сборки.

На компьютере скачайте исходники с GitHub и соберите исполняемый файл `quasarc`. Он подходит для обеих моделей.

```sh
git clone https://github.com/skrashevich/quasarc.git
cd quasarc
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o quasarc .
```

### Станция 2 через SSH

Выполните команды на компьютере. Замените `root@station2` на логин и адрес вашей колонки. У пользователя должен быть доступ на запись в `/data`. На Станциях SSH обычно слушает порт `2222`. Если у вас настроен другой порт, укажите его после `-p` во всех командах `ssh`.

```sh
STATION=root@station2
ssh -p 2222 "$STATION" 'cat > /data/quasarc && chmod 755 /data/quasarc' < ./quasarc
ssh -p 2222 "$STATION" '/data/quasarc alice-state'
```

### Станция Макс через ADB

Подключите колонку к ADB. На компьютере выполните команды ниже, когда `adb devices` показывает нужную Станцию в состоянии `device`. Если подключено несколько устройств, укажите `adb -s СЕРИЙНЫЙ_НОМЕР` вместо `adb` в командах для колонки.

```sh
adb push ./quasarc /data/local/tmp/quasarc
adb shell chmod 755 /data/local/tmp/quasarc
adb shell /data/local/tmp/quasarc alice-state
```

На обеих моделях последняя команда выведет текущее состояние Алисы. В режиме ожидания ответ может выглядеть так.

```json
{"state":"idle","code":0,"has_startup_requirements":false}
```

Команда завершается после получения ответа. В примерах ниже подставляйте вместо `quasarc` путь к установленному файлу — `/data/quasarc` на Станции 2 или `/data/local/tmp/quasarc` на Максе.

## Подключение к Go-проекту

Пакет `station` позволяет Go-приложению обращаться к сервисам колонки напрямую по TCP. В каталоге проекта с Go 1.27.1 или новее добавьте зависимость. Если пробуете пример в пустом каталоге, сначала создайте модуль командой `go mod init example.org/station-status`.

```sh
go get github.com/skrashevich/quasarc/station@latest
```

### Пример приложения

Сохраните как `main.go` в отдельном модуле с подключённой зависимостью. На Станции приложение само найдёт порт сервиса Алисы. Флаг `-port` пригодится при запуске на компьютере через туннель.

```go
package main

import (
	"context"
	"flag"
	"fmt"
	"log"

	"github.com/skrashevich/quasarc/station"
)

func main() {
	port := flag.Int("port", 0, "локальный TCP-порт сервиса aliced")
	flag.Parse()

	client := station.Client{Port: *port}
	state, err := client.AliceState(context.Background())
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(state.State)
}
```

Для запуска на колонке соберите приложение командой `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o station-status .` и скопируйте его тем же способом, что и `quasarc`. Запустите `/data/station-status` на Станции 2 или `/data/local/tmp/station-status` на Максе.

Для запуска на компьютере узнайте порт `aliced` из `quasar.cfg` колонки или из вывода установленного `quasarc -list`. Пробросьте его на локальный порт `19875`, заменив `PORT` на найденный номер.

Для Станции 2 оставьте SSH запущенным в отдельном терминале. Укажите тот же адрес, что при установке.

```sh
ssh -p 2222 -N -L 127.0.0.1:19875:127.0.0.1:PORT root@station2
```

Для Станции Макс используйте ADB.

```sh
adb forward tcp:19875 tcp:PORT
```

Теперь выполните `go run . -port 19875` на компьютере. Приложение напечатает состояние, например `idle`. Для запроса к другому сервису пробросьте его порт.

### Настройки клиента

- `station.Client{}` подключается к `127.0.0.1` и выбирает порт нужного сервиса по локальному `quasar.cfg`. Путь можно задать через `Client.ConfigPath` или переменную окружения `QUASAR_CFG`. Без них клиент ищет файл по порядку в `/system/vendor/quasar/quasar.cfg`, `/vendor/quasar/quasar.cfg` и текущем каталоге.
- `Client.Host` задаёт адрес для подключения. Ненулевой `Client.Port` указывает порт конкретного сервиса и позволяет работать без файла конфигурации.
- Каждый вызов открывает отдельное соединение. По умолчанию на запрос отводится 5 секунд. Свой срок можно передать через `context.WithTimeout`. В результатах с необязательными полями `nil` означает, что сервис не передал значение. В JSON такое поле содержит `null`.

## Команды CLI и методы Go

Команда чтения выводит один JSON-объект в stdout. Код выхода `0` означает успех, `1` — ошибку при выполнении запроса, `2` — ошибку в аргументах. Сообщения об ошибках выводятся в stderr.

| Команда | Метод `station.Client` | Что возвращает |
| --- | --- | --- |
| `alice-state` | `AliceState` | Состояние Алисы и его числовой код |
| `wifi-status` | `WiFiStatus` | Состояние подключения и уровень сигнала |
| `wifi-list` | `WiFiList` | Доступные сети, мощность сигнала, частота и признак защиты. Список может быть взят из кэша |
| `setup-status` | `SetupStatus` | Состояние настройки Станции |
| `ntp-status` | `NTPStatus` | Признак синхронизации времени |
| `brick-status` | `BrickStatus` | Состояние блокировки Станции |
| `group-status` | `GroupStatus` | Роль в группе и состояние группового прослушивания |
| `metrica-uuid` | `MetricaUUID` | UUID Метрики и идентификатор устройства, если он доступен |
| `update-status` | `UpdateStatus` | Состояние обновления, прогресс загрузки и целевая версия |
| `notification-status` | `NotificationStatus` | Наличие, количество и режим уведомлений |
| `bluetooth-status` | `BluetoothStatus` | Состояние адаптера, доступность для подключения, видимость и воспроизведение звука |
| `alarm-status` | `AlarmStatus` | Состояние будильников и таймеров, счётчики и параметры громкости |

У команды чтения флаги идут после имени, например `quasarc wifi-list -timeout 8s` или `quasarc alice-state -C /путь/к/quasar.cfg`. Через настроенный выше туннель можно запросить состояние Алисы прямо с компьютера. Для этого выполните `go run . alice-state -p 19875` в каталоге репозитория.

### Громкость и микрофон

На обеих колонках `quasarc volume get` читает громкость, а `quasarc volume set 50` устанавливает её. Аргумент — целое число от 0 до 100. Обе команды выводят подтверждённый колонкой уровень, например `{"percent":50}`. Значение округляется до ближайшей доступной ступени.

| Операция | Станция 2 | Станция Макс |
| --- | --- | --- |
| `volume get` / `set` | Чтение из `stereo_pair`, запись через `iohub_clients`. Шаг 5 % | Чтение и запись через `volume_setd`. Шкала Алисы от 0 до 10, шаг в выводе 10 % |
| `mic get` | На проверенной прошивке `aliced` пропустил поле `mics_muted` и при включённом микрофоне, и при красном индикаторе после нажатия кнопки. Команда возвращает ошибку | Читает `MicsState` из `audiod`, например `{"muted":false,"hardware_muted":null}`. Положение физического переключателя неизвестно |
| `mic mute` / `unmute` | Управление через RPC не подтверждено, код выхода 1 | Управление через RPC не подтверждено, код выхода 1 |

На Максе `volume get` показывает уровень Алисы, который может отличаться от системной громкости Android. При проверке на колонках отдельный вызов `volume get` подтвердил изменения 55 → 50 → 55 % на Станции 2 и 50 → 10 → 50 % на Максе.

Из Go эти операции доступны как функции пакета `station`: `Volume(ctx)`, `SetVolume(ctx, percent)`, `Microphone()` и `SetMicrophoneMuted(muted)`. Они находят локальные сервисы через `quasar.cfg`. Для проверки отсутствия поддержки используйте `errors.Is(err, errors.ErrUnsupported)`. Для громкости максимальное время ожидания ответа — 8 секунд.

## Диагностика

- `quasarc -list` выводит путь к конфигурации и таблицу сервисов с их TCP-портами.
- `quasarc -probe -d 300ms` проверяет соединение с сервисами из конфигурации и показывает полученные сообщения. Окно чтения задаётся для каждого сервиса отдельно.
- `quasarc -help` выводит справку по работе с шиной. Справка отдельной команды доступна, например, через `quasarc wifi-list -help`.

Для работы с кадрами из Go используйте пакет `github.com/skrashevich/quasarc/protocol`. Функция `protocol.NewBus` принимает открытое `net.Conn`. Метод `ReadFrame` читает кадр, `VisitMessages` перебирает сообщения внутри кадра, а `WriteFrame` отправляет кадр. Сигнатуры и типы доступны через `go doc github.com/skrashevich/quasarc/protocol`.

## E2E-тесты

При пуше в `main` и в pull request GitHub Actions собирает `quasarc` и запускает его внутри эмулятора КУЯСЭ 1.5.0 на прошивках Станции 2 и Мини первого поколения. В режиме `stub` тесты проверяют поиск сервиса в `quasar.cfg`, отправку команды начала диалога и ответ `alice-state` в двух форматах шины, чтение кадра `yio_audio` и код выхода при тайм-ауте. Прогон можно запустить вручную на вкладке [Actions → Kuyase E2E](https://github.com/skrashevich/quasarc/actions/workflows/kuyase.yml).

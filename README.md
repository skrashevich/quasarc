# quasarc

Клиент на Go для локальной шины Quasar. Одна и та же команда возвращает JSON на Станции 2 (Linux) и Станции Макс (Android), поэтому сторонняя программа может использовать один CLI на обеих моделях.

## Сборка и запуск

Понадобится Go 1.27.1 или новее. Один статический бинарник `linux/arm64` подходит для обеих проверенных колонок.

```sh
git clone git@github.com:skrashevich/quasarc.git
cd quasarc
go test ./...
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o quasarc .
```

Скопируйте `quasarc` на колонку и выполните `./quasarc alice-state`, чтобы получить текущее состояние Алисы. Для запуска на компьютере соберите клиент командой `go build -o quasarc .` и укажите адрес и порт проброшенного сервиса.

## Команды

| Команда | Результат |
| --- | --- |
| `quasarc alice-state` | Объект с полями `state` и `code`. Дополнительное поле `has_startup_requirements` имеет тип boolean. |
| `quasarc wifi-status` | Состояние Wi-Fi с полями `state` и `code`. Поле `signal` принимает значения `weak`, `good`, `strong`, `excellent`, `unknown` или `null` при отсутствии измерения. Возможные состояния: `not_connected`, `connecting`, `connected_no_internet`, `connected`, `not_chosen`. |
| `quasarc setup-status` | Состояние настройки. Пример: `{"state":"configured","code":2}`. |
| `quasarc ntp-status` | Результат синхронизации NTP, например `{"synchronized":true}`. |
| `quasarc brick-status` | Статус блокировки из brickd, например `{"state":"not_brick","code":2}`. |
| `quasarc group-status` | Роль в группе (`stand_alone`, `leader`, `follower`) и состояние группового прослушивания (`not_listens`, `listens`, `long_listening`). Поля `role` и `microphone_group_state` возвращают `null` при отсутствии значения. |
| `quasarc metrica-uuid` | `uuid` — UUID Метрики из `metricad`. В отдельном поле `metrica_device_id` приходит идентификатор устройства, если сервис передал его вместе с UUID. |
| `quasarc update-status` | Состояние обновления: `state`, числовой `code`, флаг `is_critical`, число `download_progress` в единицах прошивки и строка `target_version`. Известные состояния: `none`, `downloading`, `applying`. |
| `quasarc notification-status` | Признак `has_notifications`, число `count` и режим `mode` (`none`, `available`, `passive`, `unknown`). При наличии счётчика признак вычисляется как `count > 0`. В остальных случаях используется известный режим. |
| `quasarc bluetooth-status` | Пять полей типа boolean или `null`. `powered` показывает питание адаптера, `connectable` — доступность для подключения по Bluetooth Classic, `discoverable` — видимость при поиске. `audio_connected` показывает, подключён ли источник звука по A2DP, а `playing` — воспроизводит ли колонка звук с него. |
| `quasarc bluetooth on` / `quasarc bluetooth off` | Разрешают или закрывают входящие подключения Bluetooth Classic на самой колонке. Возвращают тот же JSON, что и `bluetooth-status`, после подтверждения `connectable` контроллером. Повторный вызов для уже установленного режима только читает состояние. |
| `quasarc alarm-status` | `alarm_playing` и `timer_playing` показывают, звучит ли будильник или таймер. `set_alarms_timers_count` — суммарное число установленных будильников и таймеров, `timer_count` — число таймеров. `min_volume_level` и `max_volume_level` задают уровни громкости будильника в шкале прошивки, `volume_raise_step_ms` — интервал между повышениями громкости в миллисекундах. |
| `quasarc mic get` | Состояние микрофона для Quasar и положение аппаратного выключателя, например `{"muted":false,"hardware_muted":false}`. |
| `quasarc mic mute` / `quasarc mic unmute` | Устанавливают нужное состояние и возвращают тот же JSON после проверки. Повторный вызов с той же командой сохраняет выбранное состояние. |
| `quasarc volume get` | Текущий уровень воспроизведения в процентах, например `{"percent":55}`. |
| `quasarc volume set N` | Принимает целое число 0–100 и возвращает подтверждённый уровень в том же JSON-формате. Станция 2 округляет до ближайшего шага 5%, Макс использует шкалу Android STREAM_MUSIC (на проверенной прошивке шаг 1%). |
| `quasarc wifi-list` | Отправляет запрос в Wi-Fi-сервис и возвращает первый доступный список, который может быть кэширован. Поле `networks` содержит массив точек доступа с полями `ssid`, `rssi_dbm`, `frequency_mhz` и `secure`. Отсутствующие значения представлены как `null`, пустой список как `[]`. |

При успехе команда выводит один JSON-объект в stdout и завершается с кодом 0. Неизвестное состояние получает имя `unknown` и исходный числовой код. Ошибка соединения, протокола или таймаут завершают команду с кодом 1 и диагностикой в stderr. Ошибки аргументов возвращают код 2.

У `metrica-uuid`, `update-status` и `notification-status` набор JSON-ключей одинаков на Linux и Android. Пропущенные прошивкой поля содержат `null`. Например, пустой блок обновления даёт `"state":null`, а явное значение `NONE` даёт `"state":"none"`. Нулевой прогресс передаётся числом `0`. На Максе источники обновлений и уведомлений — `updatesd` и `notificationd`, на Станции 2 — снимок `SDKState` из `iohub_clients`. Для уведомлений Android `ACTIVE` и Linux `AVAILABLE` представлены как `available`. На Станции 2 у снимка уведомлений нет счётчика.

`bluetooth-status` читает состояние плеера из `iohub_clients` на Станции 2 и из `bluetoothd` на Максе. При запуске на колонке с её системным `quasar.cfg` команда дополняет ответ показаниями контроллера и аудиопрофиля из BlueZ/BlueALSA или Android Bluetooth Manager. При явном `-p` или удалённом `-h` доступны поля шины выбранной станции. Недоступные поля равны `null`. Подключённый телефон может поставить звук на паузу, поэтому `playing` и `audio_connected` читаются отдельно.

`bluetooth on` на включённом адаптере открывает приём соединений по известному адресу. Скрытая колонка при этом остаётся скрытой для поиска. `bluetooth off` закрывает приём новых соединений. На Linux клиент использует BlueZ. На Максе с Android 9 Go-клиент обращается к службе `bluetooth_manager` через системный Binder и передаёт адаптеру его текущий таймаут обнаружения вместе с новым режимом. На проверенном Максе достаточно пользователя ADB shell. Для других версий Android предусмотрен запрос видимости к `bluetoothd`. Команда на всех платформах ждёт подтверждения от контроллера до 8 секунд и возвращает код 1, если тот не подтвердил режим.

`alarm-status` на Станции 2 читает оба признака звучания и суммарный счётчик из `iohub_clients`. При нулевой сумме и `timer_playing: false` число таймеров заведомо равно нулю. На Максе команда объединяет список таймеров и настройки из двух сообщений `alarmd`. Пустой список даёт `timer_count: 0` и `timer_playing: false`. Если состояние звучания таймера пропущено, `timer_playing` остаётся `null`, кроме случая, когда другой таймер явно звучит. На проверенной прошивке Макса поля `alarm_playing` и `set_alarms_timers_count` равны `null`, на Станции 2 это относится к трём полям громкости. Оба устройства возвращают все семь ключей.

Команды `mic` выполняются на самой колонке. Клиент определяет устройство ввода и полярность аппаратного выключателя по конфигурации ядра. Нужен доступ на чтение к отчёту GPIO в debugfs и к устройству ввода, для установки состояния — также на запись в устройство ввода. При включённом аппаратном отключении `mic unmute` завершается с ошибкой. На Станции 2 клиент сверяет программный переключатель с остановкой или запуском захвата PDM, на Максе ждёт состояния `OFF` или `ON` от `audiod`. Поле `hardware_muted` показывает положение физического выключателя при чтении.

Команды `volume` выполняются на самой колонке. На Станции 2 клиент читает состояние из `stereo_pair` и отправляет команду в `iohub_clients`. На Максе он читает и меняет громкость мультимедиа через Android AudioService. Для операций громкости таймаут составляет 8 секунд.

По умолчанию клиент работает на самой колонке, находит порт в quasar.cfg и ждёт результат до 5 секунд. Флаги идут после команды. Например, `quasarc wifi-list -timeout 8s`. Если нужный порт сервиса проброшен на компьютер, можно указать его напрямую, например `quasarc alice-state -h 127.0.0.1 -p 19875`. Формат сообщений определяется по соединению.

## Диагностика и таблица сообщений

Для диагностики шины доступны низкоуровневые флаги, например `quasarc -probe -d 300ms`. Таблица в `map_max.go` содержит номера, имена и типы полей `quasar.proto.QuasarMessage`. Источник таблицы — дескриптор `QuasarProto.proto`, встроенный в `/system/vendor/quasar/maind` прошивки Станции Макс (`yandexstation_2`).

Для составного кадра Android низкоуровневый режим `-json` выводит по одной строке на каждое сообщение в порядке передачи, включая повторяющиеся ID. Флаг `-n` считает транспортные кадры. Режим `-b64` выводит исходное содержимое каждого кадра один раз.
